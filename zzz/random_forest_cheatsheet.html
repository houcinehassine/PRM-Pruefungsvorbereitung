Entscheidungsbäume

Grundlage von Random Forest

Grundidee

  • Daten durch geschickte Fragen im Feature-Raum trennen (If-Else-Regeln).
  • Knoten = Frage, Kante = Antwort, Blatt = Vorhersage (Klasse oder Wert).

Gini Impurity (Klassifikation)

Für einen Knoten mit Klassenanteilen p_k:

G = 1 - Σ (p_k²)
  • G = 0 → reine Klasse.
  • Je gemischter die Klassen, desto größer G.

Split-Qualität

  • Berechne Gini vor Split: G_parent.
  • Berechne gewichteten Gini der Kinder: G_children.
  • Wähle Split mit maximaler Verringerung: ΔG = G_parent - G_children.

Overfitting

  • Tiefe Bäume passen Rauschen im Training zu stark an.
  • Gegenmaßnahmen: max_depth, min_samples_split, min_samples_leaf.

Random Forest (Bagging + Feature Bagging)

EnsembleVarianzreduktion

Idee

  • Viele instabile Trees werden gemittelt → robustere Vorhersage.
  • Bagging: Bäume auf Bootstrap-Samples trainieren (Stichproben mit Zurücklegen).
  • Feature Bagging: pro Split nur zufällige Teilmenge der Features betrachten.

Trainingsschema

  1. Wähle Anzahl Bäume B (n_estimators).
  2. Für jeden Baum:
    • Ziehe Bootstrap-Sample der Trainingsdaten.
    • Trainiere Decision Tree mit Feature Bagging und Gini/MSE.
  3. Vorhersage:
    • Klassifikation: Mehrheitsvotum der Bäume.
    • Regression: Mittelwert der Baum-Vorhersagen.

Out-of-Bag (OOB) Error

  • OOB-Daten: Samples, die für einen Baum nicht gezogen wurden.
  • Jeder Punkt ist OOB für ~1/3 der Bäume → kostenlose Validierung.

Random Forest in sklearn

Wichtige Klassen

  • RandomForestClassifier (Klassifikation).
  • RandomForestRegressor (Regression, z.B. RUL).

Zentrale Parameter

ParameterBedeutungTypische Werte
n_estimators Anzahl Bäume 100, 200, 500
criterion Split-Kriterium "gini", "entropy" / "squared_error"
max_depth Maximale Tiefe None, 5, 10, 20
max_features Features pro Split "sqrt", "log2", Zahl
bootstrap Bootstrap-Samples nutzen True
oob_score OOB-Validierung True / False

Code-Template (Klassifikation)

from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=200,
    criterion="gini",
    max_depth=None,
    max_features="sqrt",
    bootstrap=True,
    oob_score=True,
    random_state=42
)

rf.fit(X_train, y_train)
y_pred = rf.predict(X_test)
y_prob = rf.predict_proba(X_test)

Unsicherheit & predict_proba

Wahrscheinlichkeiten statt nur Labels

  • predict_proba(X) gibt für jede Klasse eine Wahrscheinlichkeit.
  • Unsicherheit: niedrige maximale Wahrscheinlichkeit → Modell ist unsicher.

Interpretation

  • max(p) > 0.9 → sehr sicher.
  • max(p) ~ 0.5–0.6 → Grenzfall, Fachexperte hinzuziehen.
  • In PRM: unsichere Punkte markieren und manuell prüfen.

Feature & Permutation Importance

Interne Feature Importance (Tree/Forest)

  • Basiert auf Verringerung der Impurity über alle Splits mit diesem Feature.
  • Werte normalisiert, Summe = 1.
  • Vorsicht bei korrelierten Features → verzerrte Importance.

Permutation Importance

  1. Baseline-Score auf Test-/Validierungsdaten berechnen.
  2. Für jedes Feature:
    • Werte im Testset zufällig permutieren.
    • Score erneut berechnen.
    • Importance = Baseline − permutierter Score.
  3. Großer Abfall → wichtiges Feature.

Anwendung: Sensoren auswählen

  • Wichtige Sensorarten/-positionen behalten und ausrollen.
  • Irrelevante Sensoren ggf. entfernen (Kosten, Komplexität).

Boosting & AdaBoost

Bagging vs. Boosting

EigenschaftBagging (Random Forest)Boosting (AdaBoost)
TrainingParallel, unabhängige BäumeSequentiell, jeder lernt aus Fehlern des vorherigen
FokusVarianzreduktionBiasreduktion
GewichteGleich verteiltSchwierige Punkte werden höher gewichtet

AdaBoost-Schema (für 2-Klassen-Fall)

  1. Initialisiere Gewichte w_i = 1/N.
  2. Für t = 1..T:
    • Trainiere schwachen Lerner mit Gewichten w_i.
    • Berechne gewichteten Fehler ε_t.
    • Berechne α_t = 0.5 * ln((1-ε_t)/ε_t).
    • Update: w_i ← w_i * exp(-α_t * y_i * h_t(x_i)), dann normalisieren.
  3. Finale Vorhersage: sign( Σ α_t * h_t(x) ).

PRM-Use-Cases (Kurz)

Servo Engine Fault Classification

  • Ziel: Klassifikation von Fault-Typen aus Sensordaten.
  • Random Forest + predict_proba für Unsicherheitsanalyse.
  • Unsichere Punkte zur Nachbewertung durch Fachexperten.

RUL Prediction (RandomForestRegressor)

  • RUL = Remaining Useful Life (kontinuierliche Regression).
  • RandomForestRegressor mit MSE-Splitkriterium nutzen.
  • Baselines: lineare Regression, Moving Average, konstante Vorhersage.

Baseline Models

  • Vergleich gegen einfache Modelle zwingend (Rechtfertigung ML).
  • Wenn RF kaum besser als Baseline → Modellkomplexität hinterfragen.
